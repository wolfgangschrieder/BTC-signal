# Аналитик: четыре часа и очередь задач

Отчёты DeepSeek: 00:00, 04:00, 08:00, 12:00, 16:00, 20:00 по Москве.
Контекст периодического отчёта — последние завершённые четыре часа, максимум
240 состояний. Суточный разбор — предыдущий московский день, 1440 состояний.
При старте проверяется последний завершённый слот. На штатном непрерывном запуске
это шесть периодических вызовов плюс один суточный. Старые зарезервированные
слоты не повторяются. Новый тип periodic отделён от старого tick: старые
получасовые записи не блокируют новые четырёхчасовые интервалы. Существующий лимит 50 попыток и бюджет токенов сохраняются.

## Задачи внутри системы

`intelligence.auditor_tasks` содержит очередь, приоритет, статус, контекст,
ID отчёта и отдельный результат для каждой задачи. Максимум 100 активных задач,
три за один периодический API-вызов. Срок хранения 90 дней, очистка по 500 строк.
Автоматически создаются: разбор новых завершённых прогнозов за последние два дня,
диагностика отсутствующих 1h/4h (раз в день), проверка нулевых затрат,
проект эксперимента TA/микроструктура/вместе и одна гипотеза в день.
Дедупликация не означает, что проблема исправлена: `completed` означает только
завершённый аналитический разбор. `insufficient_data` — не хватило доказательств.
Неизвестный расход после сбоя не повторяется автоматически: задача станет failed.
Оператор может создать новое задание. Эксперименты автоматически не исполняются;
аналитик не получает SQL, shell и права менять модель или порог.

Чтение очереди и результатов (без API):

```bash
docker compose --env-file deploy/.env -f deploy/compose.yml --profile auditor exec -T auditor research-os auditor-tasks
```

Добавление новой задачи оператором:

```bash
docker compose --env-file deploy/.env -f deploy/compose.yml --profile auditor exec -T auditor research-os auditor-tasks --enqueue experiment
```

Допустимы также data_quality, signal_review, hypothesis, costs. Это фиксированные
исследовательские вопросы, не произвольные инструкции или код.

## Технический контроль

При запуске и каждые 5 минут Python проверяет свежесть потоков (120 секунд;
свечи и состояния 180 секунд), очередь сигналов (пять попыток) и размер БД (18 ГБ).
Используются текущие метрики, не данные на прошедшей границе отчёта.
О проблеме отправляется отдельное локальное уведомление без DeepSeek, не чаще
одного раза на метрику за московский день, и создаётся задача диагностики.
Отсутствие 4h само по себе не техническая тревога. Контроль свободного места
5 ГБ и запрет записи при превышении storage budget сохраняются. Если БД/диск
недоступны для записи, этот DB-backed канал уведомлений тоже может не работать:
нужен отдельный внешний мониторинг. Проверки диска не гарантируют доставку тревоги.
Это периодический контроль; задержка обнаружения может достигать 5 минут.

## Telegram и полный отчёт

В Telegram — краткий комментарий, число замечаний, статусы задач и ID полного
отчёта. Все замечания и результаты сохранены в базе. Старые сообщения продолжают
доставляться частями с сохранённым курсором. До пяти попыток на часть; возможен
дубль при потере подтверждения. TTL новых периодических/технических сообщений
четыре часа, суточных сутки. Старые TTL не меняются. JSON отчёта ограничен 24 КБ,
полный текст 16000 символов, краткий текст 3500. Журнал периодических/технических
отчётов хранится семь дней, суточных 90 дней.

```bash
docker compose --env-file deploy/.env -f deploy/compose.yml --profile auditor exec -T auditor research-os auditor-report
```

Для конкретного отчёта добавьте `--id UUID`. API и Telegram не вызываются.
Сведения о поддерживаемых ТФ и настройках принадлежат auditor-контейнеру;
они не доказывают загрузку истории в другом процессе. Ссылки на evidence
подтверждают наличие метрики, а не истинность рассуждения. Нулевые издержки
относятся к EV/net, балл не является калиброванной вероятностью.

## Обновление

```bash
cd /opt/BTC-signal
git pull --ff-only origin main
docker compose --env-file deploy/.env -f deploy/compose.yml build migrate
docker compose --env-file deploy/.env -f deploy/compose.yml up -d --no-deps --force-recreate migrate
docker compose --env-file deploy/.env -f deploy/compose.yml ps -a migrate
```

После `Exited (0)` применена миграция 0019:

```bash
docker compose --env-file deploy/.env -f deploy/compose.yml --profile auditor up -d --no-deps --force-recreate auditor
```

Пересоздание app не требуется. Торговые сигналы отправляются прежним каналом.

## Исследовательский контекст v2

Во входах `project.*`: BTCUSDT linear perpetual, группы направленных/нейтральных
признаков из проверенного analysis-v3, правила OHLC-симуляции и отдельного
threshold_check. Это установленный код аналитика, не телеметрия live-app.
Есть протокол TA/микроструктура/вместе и помеченные сценарии чувствительности:
5.5 bps комиссии и 0/2/5 bps проскальзывания на сторону. Это исследовательские
допущения, не тариф пользователя; funding/спред/задержка требуют отдельных данных.
Реальные настройки затрат и торговая логика автоматически не меняются.

Задачи costs/experiment/hypothesis — DESIGN ONLY: можно подготовить план до
появления исходов. `completed` подтверждает наличие плана, а не успешный тест.
Для оценки результатов и диагноза нужны фактические доказательства; допустим
insufficient_data. Три последних результата задач передаются как непроверенные
интерпретации. Пустая история отчётов не означает «изменений нет».
Обновлённые задачи получают новые dedup keys v2; старые результаты не переписываются.
Новая миграция не нужна: собрать образ и пересоздать только auditor.

## Закрытая выгрузка отчётов

### Формат ответа и сценарии затрат

Списки evidence IDs проверяются целиком по входному snapshot. Повторы удаляются,
допускается до 128 уникальных ссылок в поле; неизвестная ссылка отклоняет ответ.
Если модель пропустила severity, замечание сохраняется с пометкой «не указана»
без придуманной оценки важности. Другие обязательные поля и лимиты проверяются.

Суточный snapshot и `python -m research_os.research.threshold_check` сопоставляют
фиксированный исследовательский сценарий 5.5/2 bps на сторону с текущими
`EXECUTION_FEE_BPS` / `EXECUTION_SLIPPAGE_BPS` на тех же кандидатах.
В JSON CLI это `configured_cost_comparison.report`, во входах аналитика —
`configured_baseline.*`. Комиссии и проскальзывание начисляются на обе стороны.
Настройки 0/0 явно помечены как оптимистичный сценарий; это не подтверждённые
тарифы счёта. Совпадение затрат не делает baseline симуляцией live-исполнения:
у него другой вход и горизонт. Сохранённые исходы прошлых сигналов не пересчитываются.

Изменения не требуют миграции. После обновления образа необходимо пересоздать
auditor; исправление действует на следующие запуски, старые failed-отчёты
не подменяются успешными.

Optional service `report-export` обновляет два пользовательских файла в закрытой
папке Google Drive. Отдельный service-account key монтируется только в экспортёр.
Это не авторизация через ChatGPT Drive: доступ VPS настраивается отдельно.
См. [DRIVE_EXPORT.md](DRIVE_EXPORT.md).

### Восстановление после ошибок (миграция 0020)

Для текущего окна daily/periodic допускаются максимум две попытки, с паузой
не менее 30 минут от начала первой. Повтор возможен только после `failed`;
`started` с неизвестным результатом автоматически не повторяется. Каждая попытка
имеет отдельный UUID и `attempt_number`; исходная ошибка и резерв токенов остаются.
Обе попытки входят в общий дневной лимит запросов и токенов. При исчерпании бюджета
новый API-запрос не запускается. Старые окна массово не переигрываются: при старте
сервис проверяет последнее закрытое четырёхчасовое окно и предыдущие московские сутки.

Монитор создаёт максимум по одной дочерней задаче для failed-задач за последние
семь дней после паузы 30 минут; `context.retry_of` связывает записи. Дочерние задачи
не порождают повторы, `insufficient_data` не повторяется. Drive-запросы исключены:
для них сохраняются собственные сроки и протокол подтверждений. Задачи оплачиваются
только как часть обычного бюджетируемого периодического отчёта, а не отдельными API-вызовами.

`history.restoration` показывает число PIT-доступных сохранённых свечей,
отсутствие raw-подтверждения, длину непрерывного восстановимого хвоста, полные
UTC-бары 1h/4h/1d и причину остановки. Это диагностика пути восстановления из БД.
`history.latest_recorded_memory` берёт записанный app размер реального ценового
буфера и его границы из последнего state не старше 10 минут; в старых states
эти поля отсутствуют. Сырые candle-события штатная шестичасовая очистка не удаляет;
отсутствие raw само по себе не доказывает причину удаления. Пропуски не заполняются.

Автообновление блокирует релизы с миграциями. Для применения из `/opt/BTC-signal`
остановите timer и дождитесь завершения уже запущенного service. Затем:

```bash
sudo systemctl stop btc-signal-auto-update.timer
# Убедитесь, что service уже завершён:
systemctl is-active btc-signal-auto-update.service
# Продолжайте только после inactive (или failed), не во время activating/active.
git pull --ff-only origin main
# Внешнюю резервную копию БД создайте по инструкции deploy/README.md.
docker compose --env-file deploy/.env -f deploy/compose.yml build migrate
# Остановите только аналитик на время изменения его журнала:
docker compose --env-file deploy/.env -f deploy/compose.yml --profile auditor stop auditor
docker compose --env-file deploy/.env -f deploy/compose.yml run --rm migrate
# Продолжайте только при exit code 0:
docker compose --env-file deploy/.env -f deploy/compose.yml --profile auditor --profile report-export up -d --no-deps --force-recreate app auditor report-export
sudo systemctl start btc-signal-auto-update.timer
docker compose --env-file deploy/.env -f deploy/compose.yml --profile auditor logs --tail 80 auditor
```

Команды без updater override намеренно пересоздают указанные сервисы новым
`btc-signal:local`. После успешной ручной миграции текущий git HEAD становится
базой следующих автоматических обновлений. Миграция не стирает отчёты; downgrade
откажется восстанавливать старую уникальность, если уже накоплены две попытки.
Новый daily считается восстановленным только после `status=completed` и появления
свежего суточного окна на Drive; новый SHA или heartbeat этого не подтверждают.
