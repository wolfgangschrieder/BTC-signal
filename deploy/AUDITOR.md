# Аналитик: четыре часа и очередь задач

Отчёты DeepSeek: 00:00, 04:00, 08:00, 12:00, 16:00, 20:00 по Москве.
Контекст периодического отчёта — последние завершённые четыре часа, максимум
240 состояний. Суточный разбор — предыдущий московский день, 1440 состояний.
При старте проверяется последний завершённый слот. На штатном непрерывном запуске
это шесть периодических вызовов плюс один суточный. Старые зарезервированные
слоты не повторяются. Существующий лимит 50 попыток и бюджет токенов сохраняются.

## Задачи внутри системы

`intelligence.auditor_tasks` содержит очередь, приоритет, статус, контекст,
ID отчёта и отдельный результат для каждой задачи. Максимум 100 активных задач,
три за один периодический API-вызов. Срок хранения 90 дней, очистка по 500 строк.
Автоматически создаются: разбор новых завершённых прогнозов за последние два дня,
диагностика отсутствующих 1h/4h (раз в день), проверка нулевых затрат,
проект эксперимента TA/микроструктура/вместе и одна гипотеза в день.
Дедупликация не означает, что проблема исправлена: `completed` означает только
завершённый аналитический разбор. `insufficient_data` — не хватило доказательств.
Неизвестный расход после сбоя не повторяется автоматически: задача станет failed.
Оператор может создать новое задание. Эксперименты автоматически не исполняются;
аналитик не получает SQL, shell и права менять модель или порог.

Чтение очереди и результатов (без API):

```bash
docker compose --env-file deploy/.env -f deploy/compose.yml --profile auditor exec -T auditor research-os auditor-tasks
```

Добавление новой задачи оператором:

```bash
docker compose --env-file deploy/.env -f deploy/compose.yml --profile auditor exec -T auditor research-os auditor-tasks --enqueue experiment
```

Допустимы также data_quality, signal_review, hypothesis, costs. Это фиксированные
исследовательские вопросы, не произвольные инструкции или код.

## Технический контроль

При запуске и каждые 30 минут Python проверяет свежесть потоков (120 секунд;
свечи и состояния 180 секунд), очередь сигналов (пять попыток) и размер БД (18 ГБ).
Используются текущие метрики, не данные на прошедшей границе отчёта.
О проблеме отправляется отдельное локальное уведомление без DeepSeek, не чаще
одного раза на метрику за московский день, и создаётся задача диагностики.
Отсутствие 4h само по себе не техническая тревога. Контроль свободного места
5 ГБ и запрет записи при превышении storage budget сохраняются. Если БД/диск
недоступны для записи, этот DB-backed канал уведомлений тоже может не работать:
нужен отдельный внешний мониторинг. Проверки диска не гарантируют доставку тревоги.
Это периодический контроль; задержка обнаружения может достигать 30 минут.

## Telegram и полный отчёт

В Telegram — краткий комментарий, число замечаний, статусы задач и ID полного
отчёта. Все замечания и результаты сохранены в базе. Старые сообщения продолжают
доставляться частями с сохранённым курсором. До пяти попыток на часть; возможен
дубль при потере подтверждения. TTL новых периодических/технических сообщений
четыре часа, суточных сутки. Старые TTL не меняются. JSON отчёта ограничен 24 КБ,
полный текст 16000 символов, краткий текст 3500. Журнал периодических/технических
отчётов хранится семь дней, суточных 90 дней.

```bash
docker compose --env-file deploy/.env -f deploy/compose.yml --profile auditor exec -T auditor research-os auditor-report
```

Для конкретного отчёта добавьте `--id UUID`. API и Telegram не вызываются.
Сведения о поддерживаемых ТФ и настройках принадлежат auditor-контейнеру;
они не доказывают загрузку истории в другом процессе. Ссылки на evidence
подтверждают наличие метрики, а не истинность рассуждения. Нулевые издержки
относятся к EV/net, балл не является калиброванной вероятностью.

## Обновление

```bash
cd /opt/BTC-signal
git pull --ff-only origin main
docker compose --env-file deploy/.env -f deploy/compose.yml build migrate
docker compose --env-file deploy/.env -f deploy/compose.yml up -d --no-deps --force-recreate migrate
docker compose --env-file deploy/.env -f deploy/compose.yml ps -a migrate
```

После `Exited (0)` применена миграция 0019:

```bash
docker compose --env-file deploy/.env -f deploy/compose.yml --profile auditor up -d --no-deps --force-recreate auditor
```

Пересоздание app не требуется. Торговые сигналы отправляются прежним каналом.
