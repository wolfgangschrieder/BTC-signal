# Аналитик: 30 минут и полный отчёт

Этот документ уточняет первоначальный раздел аналитика в README.
Периодический запуск — на границах :00/:30 UTC, контекст — скользящий час,
до 120 состояний. Суточный разбор — предыдущий московский день, до 1440 состояний.
При старте проверяется последний завершённый интервал; зарезервированные
интервалы не вызывают API повторно. До 50 запросов за московский день,
включая суточный; старые запросы текущего дня тоже учитываются. Ограничения
токенов, памяти 256 MB и диска 18 GB/5 GB сохраняются.

Контекст содержит предыдущие метрики того же типа отчёта, поддерживаемые
таймфреймы и настройку live-истории. Это сведения установленного кода и
текущего контейнера, а не проверка другого процесса. Отсутствие признака
не доказывает сбой источника; IDs калибровок не подтверждают их загрузку
или качество. Raw score — направленный балл; расходы относятся к EV и
симулированной net return. Инструкция запрещает повторять замечания без
новых оснований, но не гарантирует семантическую дедупликацию.

## Чтение полного сохранённого отчёта

После обновления образа и миграции:

```bash
docker compose --env-file deploy/.env -f deploy/compose.yml --profile auditor exec -T auditor research-os auditor-report
```

Для конкретного отчёта добавьте `--id UUID`. Читается последний завершённый
JSON из БД и форматируется без обрезки. API и Telegram не вызываются.
Так можно прочитать полный старый отчёт, даже если сообщение было обрезано.

Численная статистика системы — отдельная команда:

```bash
docker compose --env-file deploy/.env -f deploy/compose.yml exec -T app research-os observation-report --hours 24 --limit 1440
```

## Telegram

Python делит полный текст без потери символов на нумерованные части до
3500 UTF-16 units. Одна часть отправляется за итерацию очереди (около 10 секунд).
Номер следующей части хранится в PostgreSQL. Подтверждённые части не повторяются;
при падении между Telegram-ответом и подтверждением в БД дублирование текущей
части возможно. До пяти попыток на часть. TTL нового периодического отчёта
40 минут после конца интервала, суточного 24 часа; TTL старых записей не меняется.
Полный текст в БД ограничен 16000 символами, JSON 24000 bytes. Хранение —
7 дней для периодических, 90 для суточных; удалённые отчёты недоступны.

## Обновление

```bash
git pull --ff-only origin main
docker compose --env-file deploy/.env -f deploy/compose.yml build migrate
docker compose --env-file deploy/.env -f deploy/compose.yml up -d --no-deps --force-recreate migrate
docker compose --env-file deploy/.env -f deploy/compose.yml ps -a migrate
```

После `Exited (0)`:

```bash
docker compose --env-file deploy/.env -f deploy/compose.yml --profile auditor up -d --no-deps --force-recreate auditor
```

Пересоздавать app для этих изменений не требуется.
