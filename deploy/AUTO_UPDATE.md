# Автообновление и автономная работа

Установщик выполняется один раз на VPS:

```bash
python3 /opt/BTC-signal/deploy/install-auto-update.py
```

Нужны root, Docker Compose, systemd, Git и Python3; репозиторий должен быть
чистой main в /opt/BTC-signal с origin именно wolfgangschrieder/BTC-signal.
Ключей SSH/GitHub для публичного репозитория не требуется. Никакие ключи или env
не печатаются. Ранее созданный Drive экспорт должен быть настроен отдельно.

Установщик копирует отдельный хостовый агент и создаёт systemd service/timer.
Таймер проверяет релиз раз в час и после запуска системы. Агент принимает
только CI workflow ci.yml с успешным последним push-run main для точного SHA.
На сервере ограничен один запуск (flock); отсоединённая ветка или локальные
изменения блокируют обновление. Последний признанный неудачным SHA не повторяется:
нужен новый исправленный commit или отдельное ручное решение оператора.

deploy/auto-release.json должен точно разрешать обновление с migration_policy=none.
Любое изменение alembic/ или alembic.ini блокирует автоматическое применение.
Этот вариант намеренно не запускает миграции, не откатывает DB и не делает backup
перед каждым кодовым обновлением; автоматические миграции/backup потребуют отдельного
протокола и проверки восстановления. Только app, включённый auditor и настроенный
report-export. PostgreSQL, volumes, торговые настройки, секреты и другие проекты
не пересоздаются. Пользовательский env сохраняется.

Перед сборкой нужно минимум 8 decimal GB свободного места, после минимум5 GB.
Собирается отдельный btc-signal:auto-SHA image. Старые images каждого сервиса
сохраняются как rollback. Compose override runtime-compose.json связывает выбранные
сервисы с конкретным образом; общий btc-signal:local не перезаписывается агентом.
Up выполняется --no-deps --force-recreate только для выбранных сервисов.
Новый релиз может изменить поведение кода и разрешённые defaults; реальные env
параметры остаются пользовательскими. Это не разрешение модели исполнять код с Drive.

Проверка до8 минут: контейнеры Running, без OOM/Restarting и новый decision_time
BTCUSDT после начала развёртывания (свежесть до180 секунд). Это не доказательство
доходности, корректного DeepSeek ответа или успешной Telegram доставки. Ошибки LLM
остаются в operations/analyst_attempts и требуют отдельного исправления.

При ошибке агент возвращает предыдущий git HEAD и точные прежние image IDs,
повторно проверяет новые решения рынка и фиксирует rolled_back/rollback_failed.
Если процесс убит/сервер перезагружен в состоянии deploying, следующая проверка
использует durable rollback record. При некорректном record или ручных изменениях
репозитория вмешательство обязательно: чужие правки не перезаписываются.

Удаляются только неиспользуемые updater-managed образы, кроме текущего и rollback,
без force. PostgreSQL volumes и чужие Docker images не удаляются. Build cache/WAL
могут расти; нехватка места блокирует обновления, не запускает общую очистку диска.

Статус хранится в deploy/deployment-status/status.json. Эта ignored директория
монтируется read-only только в report-export; на Drive выходят allowlisted
status/stage/SHA/время/код причины, не env, команды, image history или секреты.
При полном отказе сервера старый Drive heartbeat остаётся единственным наблюдением;
надёжный внешний монитор надо настроить отдельно.

Проверка таймера:

```bash
systemctl status btc-signal-auto-update.timer --no-pager
```

Разовый запуск уже установленного агента:

```bash
systemctl start --no-block btc-signal-auto-update.service
```

Пауза:

```bash
systemctl disable --now btc-signal-auto-update.timer
```

После установки не выполнять ручные git pull/reset и compose recreate одновременно
с агентом. Для обслуживания сначала остановить timer и дождаться завершения service.
Автономные ChatGPT проверки запускаются планировщиком приложения, не этим агентом;
каждая подтверждает факты на Drive и CI, ведёт максимум одну работу за цикл и
не считает LLM agreement доказательством прибыли.
